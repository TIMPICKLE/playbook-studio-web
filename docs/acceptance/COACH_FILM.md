# 数字战术板教练讲解验收

桌面编辑器在战术标题旁提供「讲解」。试点的主任务是让教练在同一张球场上找到四分卫出手的一刻，解释 H、Y 谁更深，以及两人何时拉开距离。验证使用编辑器内置的 Mesh、Inside Zone 和可导入的 Play A、Play B。

## 验收任务

| 需求 | 复现操作 | 可观察结果 |
| --- | --- | --- |
| F1 进入与返回 | 选择球员或留下一条未完成路线，打开讲解、改停点并按 Esc，重复三次 | 初入从起点全览。返回后原选中、工具、缩放、滚动、未提交输入及撤销记录可继续使用。查看或选人不写入战术文件。 |
| F2 事件 | Mesh 依次点出手、到达，再用上一事件和下一事件返回。换 Play B 和 Inside Zone | Mesh 为 2.0 和 3.0 秒，Play B 出手为 2.35 秒。Inside Zone 的球仍由 RB 持有，时间轴不生成传球事件。 |
| F3 聚焦 | 从球场和位置列表各选一人，再选第三人、取消或明确替换 | 球员有轮廓、开球站位与近期实线路径。重叠和同名球员可通过列表定位。第三人由用户指定替换哪位。 |
| F4 纵深 | Mesh 选 H、Y，比较 1.0 和 2.0 秒。换明暗、固定参考帧后再倒拖 | 纵深沿进攻方向计算。H 分别深 1.0 和 3.0 码。两种主题一致。显示精度内两人相同，显示同一纵深。无场地比例时只说明相对位置。 |
| F5 时间轴 | 播放、拖到末尾、倒拖到 2.5 秒，再通过事件回到出手 | 拖动即暂停，球、人和读数来自同一帧。出手边界球仍在 QB 位置，2.5 秒在传球中，3.0 秒到达设计接球位置。 |
| F6 状态与兼容 | 切后台、再进房间、模拟图形上下文丢失、更新战术或删除已选球员。打开原图和纯布阵 | 暂停无持续绘制；兼容场地保留时刻与焦点。修订使相应标记失效时提示。原图可看图，纯布阵可比较站位。尊重减少动态，事件和焦点均可由键盘操作。 |
| 本机课件 | 用课件入口设置三处停点，逐题展示，揭示教练答案，再保存、重开或修改原路线 | 每个停点恢复时间和选人。提问时可隐藏后续路线。载入按工作区、战术及编排版本校验。原战术仍可独立编辑。 |
| 轻量对照 | 比较常规演练、常规演练加事件按钮和完整讲解台 | 三个条件读取同一战术事件。两个对照入口保留常规场地和传输控件，能独立检验事件定位的收益。 |

## 助手和人工操作的验收

| 用同一助手连续发话 | 查看真实结果 |
| --- | --- |
| 「停在出手，比较 H 和 Y。固定这一帧，再回到 1.0 秒。」 | Mesh 显示当前 H 深 1.0 码，参考帧仍为 2.0 秒、H 深 3.0 码。下一轮直接读取同一房间状态。 |
| 「把这个停点做成一个问题，写好答案，保存到本机。」 | 课件面板显示同一问题和选人。默认读帧省略教学答案，揭示后可读，教师备课可显式读取答案。重新载入可恢复。本机课件不会修改共享战术或增加撤销记录。 |
| 从助手进入讲解，在讲解台继续发话，再返回编辑 | 使用原会话和输入框。模型能发现 19 种房间命令，课件命令有 16 种动作。 |
| 同名球员、只有跑球或静态原图、手机与常规对照 | 工具返回具体错误、候选或可用操作。查看权限允许制作个人本机课件，团队战术写入受原有角色控制。 |

助手在普通桌面战术上可先发现课件，再按需打开。检查课件状态不会把用户带离编辑器。纯原图、移动端与常规对照会返回各自实际可用的能力。主持人显式在助手中查看答案时，投屏仍保持提问状态。

回归覆盖 OpenAI Chat Completions、Responses 和 Anthropic Messages，使用可复现的模型工具回复。客户端工具实际操作编辑器，云端测试实际运行 Worker 请求处理、权限校验、SQLite 数据库和同一回合的续调。没有调用付费供应商检验自然语言识别率。[操作协议](../COACH_FILM_COMMANDS.md) · [端到端测试](../../tests/coach-film-assistant-e2e.test.mjs) · [供应商及云端工具测试](../../tests/assistant-film-tools.test.mjs)

## 公开站点回归

已在原公开站点 v61 的桌面编辑器中打开 Mesh，从标题旁进入「讲解」。点「出手 2.0s」、选 H 和 Y、固定参考帧，再拖至 1.0 秒，侧栏同时显示当前 H 深 1.0 码、参考帧 H 深 3.0 码。打开场内助手后，球场和两个读数仍可查看。在助手中选用比较球员的示例，指令会进入原输入框。点「返回编辑」后，战术名称仍为 Mesh，撤销仍处于禁用状态。该线上操作未向模型供应商发送请求。[公开桌面入口](https://playbook-studio-tim.kind-wolf-6204.chatgpt.site/editor/local#editor) · [v61 线上截图](evidence/coach-film/live-v61.jpg)

## 工程实测

全量 Node 回归 968/968 通过。后续 AI 能力发现与错误回执的 22/22 项专项同样通过。本地生产构建、静态 Pages 构建、语法检查、TypeScript 检查和 PDF 知识导入的 4 个 Python 用例通过。每条路径的状态由软件和真人两部分各自验收。

### 从正式编辑器入口测量

用正常启动的 `index.html#editor` 载入 22 人、10 条路线的战术。在页面及字体加载完成、确认标题旁的讲解按钮可见后进入讲解，聚焦 H 和 Y。自动选择了 SVG。云 Chromium 156 前台运行，视口 1363 × 936、DPR 1，每轮播放 30 秒并做 32 次双向拖动。表中记录的是浏览器回调观测到对应画面的时间。

| 轮次 | 播放帧间隔 P95 | 帧间隔超过 33.3 ms | 拖动至场地数据提交 P95 | 拖动至下一次画面采样 P95 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 16.8 ms | 3.66% | 33.6 ms | 1018.7 ms |
| 2 | 1016.5 ms | 100.00% | 13.5 ms | 1027.4 ms |
| 3 | 1016.5 ms | 91.67% | 10.4 ms | 1026.8 ms |

第一轮虽然有一半以上帧在 16.7 ms 左右，最长一帧仍超过一秒。后两轮大部分帧超过 33.3 ms。常规编辑器静置和讲解台静置的帧间隔 P95 同为 1016.5 ms。暂停后 10 秒没有场地 DOM 更新。此环境的 SVG 回放稳定性与拖动至可见画面的延迟未达到试点指标。真实集显、独显和投屏仍待测。以上采样的应用入口、源文件指纹、原始间隔及各次拖动用时均随报告保存。[正常入口逐帧数据](evidence/coach-film/normal-entry.json)

### 辅助对照

云 Chromium 156，1363 × 936 CSS 像素、DPR 1。测试战术含 22 名球员与 10 条路线。早期诊断页由采样脚本加载编辑器。第一轮自动选择 SVG，三次 30 秒回放的帧间隔 P95 均为 1016.5 ms；32 次双向时间跳转的输入至显示采样 P95 分别为 1022.0、1043.3、1209.6 ms。暂停前台观察 10 秒没有场地 DOM 更新。该结果未达到 60 Hz 桌面验收线。[原始采样](evidence/coach-film/first-svg.json)

空页三轮的帧间隔 P95 为 16.7、16.7、16.8 ms。同一浏览器文档的分段测量中，进入原有常规编辑器后就出现 1016.5 ms，数字编辑、讲解静置与讲解播放的 P95 也相同。另一次隔离中，静态 HTML 壳在加载样式前仍为 16.7 ms；动态插入 24 个样式表、尚未启动应用时已出现约一秒间隔。随后禁用样式和移除产品 DOM 未立即恢复。以全新顶层文档独立复验，13 组中只有动态插入整组样式出现 1016.5 ms；HTML 正常声明 24 份样式、打包成一份、内联和空文件对照均为 16.7–16.8 ms。单凭动态试验不能将真实入口的表现归因为样式数量。[隔离记录](evidence/coach-film/isolation.json) · [独立文档样式对照](evidence/coach-film/style-matrix.json) 硬件 WebGL 的集显、独显和物理投屏仍待测。[空页对照](evidence/coach-film/bare-clock.json) · [同页分阶段数据](evidence/coach-film/paired-profile.json) · [复测方法](../../scripts/bench-digital/coach/README.md)

在同一诊断入口强制 SVG 复测，三轮拖动输入至场地标记提交的 P95 为 7.6、18.2、33.8 ms；到下一次浏览器显示采样的 P95 为 1020.7、1019.2、1036.0 ms，回放帧间隔 P95 为 1016.5、1016.5、1033.1 ms，三轮超过 33.3 ms 的比例均为 100%。10 秒静置场地修改为 0。输入落地和看到它是两个指标。此份实测的 SVG 显示门槛仍未通过。[该入口的强制 SVG 逐帧数据](evidence/coach-film/final-svg.json)

## 使用试点的边界

Play A 在 2.0 秒出手时 H 深 3.0 码；Play B 在 2.35 秒出手时 Y 深 4.0 码。它们可通过编辑器的导入功能追加。正式试用需要教练先审核题目与配对难度，再由 4 位教练、4 位球员完成交叉任务，单独记录盲辨、成功人数、用时和复用。招募、投屏观察及线下设备数据尚待实测。公开版本通过手动入口开放，常规编辑仍是起始画面。[试题、记录工具与判定办法](../COACH_FILM_PILOT.md)

教练写下的预期答案、问题和停点存于当前设备，适合用同一台电脑主持战术会。错跑重演、读防分岔、职责接力和跨阵型迁移的教学效果需由教练复核。[实验操作说明](../COACH_FILM_PILOT.md#自愿教学扩展试验)

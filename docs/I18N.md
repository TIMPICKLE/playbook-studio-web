# Interface localization

The editor stores the selected interface language under `playbook-studio.locale` in browser local storage. The supported locales and message lookup live in `web/i18n.js`; Chinese (`zh-CN`) is the fallback. The editor, cloud screens and AI/Madden modules use `t(key, params)`, with `{name}` placeholders for dynamic values. The GitHub Pages landing page shares the language preference and keeps its own landing-page messages.

Message dictionaries are in `web/locales/`: the main editor uses `zh-CN.js` and `en.js`; `cloud.*`, `madden-ai.*`, `support.*`, and `landing.*` group messages by feature. Keep the same keys and placeholder names in each translation. Pass user-supplied play titles, names, notes and other content as data; do not translate or rewrite saved content.

To add a language:

1. Add corresponding dictionaries for each feature in `web/locales/`, preserving keys and placeholders.
2. Register the locale and dictionaries in `web/i18n.js`; add it to the editor and landing language selectors, and register the landing dictionary in `web/migrate.js`.
3. Add the new resource files to `web/sw.js` so the offline editor can load them, and update the AI response language instructions in `server/matchup-locale.mjs` if the language should be supported there.
4. Run `npm test` and verify the login, editor, cloud sync states, Madden library, AI analysis and landing page in the new language, including offline and error states.

Switching languages reloads the interface. The editor blocks switching when an edit is unsaved, synchronization is pending or a conflict is unresolved; an in-progress drawing requires confirmation. Existing user data remains in its original language. Translation coverage should be checked when introducing new UI and server errors.

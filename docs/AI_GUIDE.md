# AI 功能使用指南

**简体中文** · [English](AI_GUIDE.en.md) · [返回 README](../README.md)

Playbook Studio 有两个 AI 入口：战术板助手负责编辑和操作，攻防对位分析负责结合图面与资料讨论可能的比赛情景。两者都面向**美式橄榄球**，共用模型连接设置，输入和执行流程各有用途。

本文描述当前仓库实现。在线站点使用的版本以实际部署记录为准。

## 先选对入口

| 想完成的事 | 从哪里进入 | 是否需要 API Key |
|---|---|---|
| 添加防守、修改路线、管理战术、控制演练或导出 | 工作台 → **编辑战术本** → 球场边缘 **AI** | 发送助手指令需要 |
| 查看攻防图面简报和检索到的教练资料 | 工作台 → **AI分析战局** | 不需要 |
| 结合资料生成有条件的攻防情景 | 同一分析页面 → 填写模型设置 → **分析对局** | 需要 |

可以先打开[免登录演示](https://timpickle.github.io/playbook-studio-web/)体验。演示使用浏览器本地数据与内置攻防示例；团队共享使用[云端版](https://playbook-studio-tim.kind-wolf-6204.chatgpt.site/editor/)。

## 5 人腰旗与 AI

先新建 **5 人制腰旗**战术，或让助手「新建一张 5 人腰旗 Trips 进攻」。在该图上可说「添加 5 人对手，保留进攻」或「让中锋 C 跑接球路线」。助手、图面简报和模型分析都会收到当前腰旗制式；不会把中锋默认当作阻挡锋线，也不会把 11 人保护、擒抱或接触式教学直接当作腰旗规则。

腰旗分析暂不采用尚未适配的内置 11 人教练资料；可导入自己的腰旗知识包，结合图面分析。冲传、QB 跑球和场地码数仍需提供所属赛事规则；五人腰旗对十一人阵型会提示制式不一致。

明确要求 **4–3 防守**仍会生成完整 11 人，不会截成五人；Madden 也是 11 人战术来源。默认人数设置不会自动转换现有战术。更多操作见[腰旗使用说明](USER_GUIDE.md#5-人制腰旗)。

## 连接模型

两个 AI 入口在云端和免登录版使用相同的服务商与 API 格式设置：**先选服务商，再选 API 格式，最后填写模型 ID 和 API Key**。预设服务商不需要手填 URL。

| 服务商 | 可选 API 格式 |
|---|---|
| DeepSeek | OpenAI Chat Completions、Anthropic Messages |
| Anthropic / Claude | Anthropic Messages |
| OpenAI | OpenAI Chat Completions、OpenAI Responses |
| OpenRouter | OpenAI Chat Completions、OpenAI Responses |
| 其他兼容服务 | 三种格式均可选择；需要填写自定义 HTTPS 地址 |

战术板助手和云端对位分析会调用工具，应选择**在所选 API 格式下支持工具调用**的模型。免登录对位分析仍是单次请求，但模型也需返回要求的结构化分析结果。支持某种 API 格式不代表服务商的每个模型都支持该格式或所需能力。

### 自定义地址怎样填写

可填写 HTTPS 基础地址，也可粘贴完整端点。应用保留已有路径前缀，只添加或替换末端协议路径：

| API 格式 | 自定义地址的末端路径 | 基础地址为 `https://gateway.example/team/v1` 时 |
|---|---|---|
| OpenAI Chat Completions | `/chat/completions` | `https://gateway.example/team/v1/chat/completions` |
| Anthropic Messages | `/messages` | `https://gateway.example/team/v1/messages` |
| OpenAI Responses | `/responses` | `https://gateway.example/team/v1/responses` |

例如，将上表的完整 Chat Completions 地址粘贴后切换到 Messages，会得到同前缀的 `/team/v1/messages`。应用**不会擅自补上 `/v1`**；若服务要求 `/v1`、`/api` 或其他网关路径，需按服务商文档填写。不要在 URL 中放用户名、密码、查询参数或片段；使用标准 HTTPS 端口。

免登录版由浏览器直连，包括自定义服务，服务端必须允许浏览器跨域请求（CORS）。云端版由服务器请求；自定义主机需要管理员先加入允许列表，也不能指向本机或内网地址。界面可配置并不表示浏览器网络或云端主机权限一定允许访问。

有些服务把接口称为「Claude Code Messages」：在这里它指 **Anthropic Messages API 格式**，不是 Claude Code 登录、订阅账号或本地 CLI。需要的是该 API 服务提供的地址、模型 ID 和密钥。

### 切换格式与密钥

同一服务商内切换 API 格式会保留模型 ID、密钥和自定义地址；发送时按新格式解析实际端点。切换服务商会采用新服务商的默认模型与格式，并清空密钥和自定义地址，避免误用上一家的凭据。

两个 AI 入口共享服务商、API 格式、模型、自定义地址和当前会话的 Key；在一个入口确认连接配置后，另一个入口沿用。非密钥连接偏好保存在本机浏览器；**Key 只在当前页面内存中，刷新后需重填**，不会写入战术、导出或持久存储。退出账号或失去访问权限时清理凭据。

调用消耗所选服务商的额度。OpenAI Responses 由应用处理无状态历史与工具结果，用户无需管理 `response_id` 或提供上一轮响应 ID。

## 战术板助手：从指令到结果

1. 打开需要操作的战术，点击 **AI**。桌面上 AI 与属性共用任务区，也可选择浮动；触屏可收起面板查看球场。可以输入文字，或在浏览器支持时用麦克风听写，核对文字后发送。
2. 直接说明目标，例如「在这张 Mesh 上添加完整的 4–3 防守，保留进攻和路线」。无需提供内部 ID，也无需先手动放置新球员。
3. 检查返回的结果。数据修改会先显示图面预览或变更清单；视图和演练操作会执行后报告状态；文件流程会显示 **继续**。
4. 对数据修改，可先演练预览，再选择 **应用**或**放弃**。应用后可撤销整组修改。
5. 如果画布、人员或阵型在等待期间发生相关变化，重新生成或检查刷新后的预览，再应用。

「添加防守阵型／找 Madden 战术」是指令示例与偏好，不是能力开关。查看防守图时仍可查找进攻战术；编辑、检索、视图等功能遵循实际权限和设备条件。

### 可以怎样说

| 目标 | 指令示例 | 应检查的结果 |
|---|---|---|
| 添加防守 | 「添加完整的 4–3 防守，保留进攻」 | 新增 11 名防守；进攻与原有路线保留 |
| 重置防守 | 「把现有防守重置为 4–3」 | 明确替换旧防守，清理旧防守路线及失效引用 |
| 添加和设置球员 | 「添加一名蓝色方形 LB」 | 新标记的位置、标签、颜色和形状 |
| 调整已有球员 | 「把左侧 X 向外移动 3 码」 | 目标球员及其附属路线一起调整 |
| 修改路线 | 「左侧大外接跑 12 码 post」 | 目标、实际深度、向内折点和边界调整 |
| 有序阻挡 | 「C 先挡正前方 DT，再去挡名叫 Alex 的 LB」 | 两名真实目标及接触顺序；重名时先澄清 |
| 多人阻挡 | 「OL 全线向左做 zone 阻挡」 | 实际参与球员、分配目标与生成路径 |
| 预动和后续路线 | 「Z 先向左 jet motion，再跑 flat」 | 预动终点与后续路线起点、时序衔接 |
| 传球和时序 | 「传给 Y，2.5 秒出手、3.5 秒到达」 | 持球人、接球人和时间设置 |
| 区域与文字 | 「画左侧 deep third」「在 X 旁标注外侧释放」 | 区域位置、尺寸和标签；文字内容 |
| 战术属性与整体编辑 | 「改名为 Red Mesh，再左右镜像」 | 名称及全部相关对象的镜像预览 |
| 战术本与人员 | 「复制当前战术」「保存当前阵型」「应用已有的首发人员组」 | 新战术、模板名称或实际匹配的已有球员 |
| 视图和布局 | 「切浅色球场，隐藏码线」「展开球场并放大到 150%」 | 设备上的实际视图，不改变战术坐标 |
| 演练与编辑控制 | 「半速循环演练」「暂停到 2 秒」「撤销上次修改」 | 播放、时间轴、速度或已有历史记录 |
| 导航与筛选 | 「切到防守战术本」「筛选 Mesh」「打开属性栏」 | 列表、当前战术和对应面板 |
| 目录检索与导入 | 「找几套适合进攻 Cover 3 的 Madden 战术」 | 实际目录候选、可编辑状态与推荐条件 |
| 文件与打印 | 「导出 SVG」「打印当前战术的腕带版」「导入本地战术本」 | **继续**按钮及随后打开的真实流程 |

球员可按位置、姓名、号码或相对站位定位，例如 `X`、`#12`、`Alex`、左侧大外接。多个对象匹配时补充侧别或姓名。对同组新建对象，助手可使用局部引用组织后续操作，用户无需复制内部 ID。

### 4–3 防守的具体含义

添加的是完整 **4 名锋线、3 名线卫、4 名后卫**，固定 11 名防守球员，不会因工作区选择七人制而截断后仍标作 4–3。当前图上已有防守时，不会重复堆放另一组；需要替换时请明确说「重置」。

4–3 只是人员与起始站位，**不自动代表 Cover 2、Cover 3 或任何匹配规则**。添加后可继续指定覆盖和责任。普通的「添加防守」保留进攻；「替换整个起始阵型」是另一项操作，会清除当前路线、区域和文字，应用前应核对变更清单。

### 哪些操作需要确认

| 结果 | 何时生效 | 撤销与后续操作 |
|---|---|---|
| 球员、路线、区域、文字、属性、阵型等改图 | 点击 **应用**后 | 整组进入一次编辑历史；可撤销 |
| 新建、复制、删除战术或保存阵型等战术本变更 | 查看变更清单并点击 **应用**后 | 整组撤销；至少保留一套战术 |
| 视图、布局、导航和演练控制 | 助手完成操作后 | 返回实际状态；显示偏好不写入战术数据 |
| 文件、打印和需要继续设置的面板 | 点击 **继续**后打开流程 | 仍需选择文件、确认导入或完成打印 |

`awaiting_user` 表示等待用户继续，不表示文件已经导入、下载已保存或打印已完成。导出开始后检查浏览器下载；打开打印面板后仍需执行打印。涉及先改图再导出的任务，可先应用改图，再发送导出指令。

预览未应用时不保存战术。若其他编辑已发生，助手的专用撤销可能失效，此时使用编辑器有操作名称的撤销／重做。

### 连续对话与草稿

- 未应用时可以继续说「再深两码」「把刚才那名外接手向左移」；新修改累积在同一草稿，仍需确认后写入。收起助手不会放弃提案。
- 多轮提案可按整轮修改组选择，点击 **更新预览**后再应用；存在前后依赖时需保留必要组，不能直接提交残缺修改。也可撤回最后一步或放弃整个提案。
- 对话记录标明待确认、已应用、已撤销、失败等状态；执行中显示实际阶段，失败保留可恢复输入及有效提案。多个可能目标会提供候选供核对。
- 会话按工作区和战术隔离。返回同一战术可回看历史；切换战术或相关对象变化后，旧预览需重新生成，不能跨图直接应用。对话保存在页面内存中，刷新后不保留。

界面会携带近期对话与仍存在的目标，但这不保证真实模型每次都能理解代词。先核对高亮和预览；本轮真实模型理解质量的验证边界见 [UX 报告](UX_REDESIGN.md)。

### 查询停止与查看过程

战术板助手已取消每次任务 **6 轮模型请求／10 次工具调用**的固定配额，也没有整次任务 90 秒总时限。有新信息时可以继续查询；连续三轮没有新增有效信息时，会要求模型用已有信息结束或澄清。单次模型 HTTP 请求和响应读取仍有 90 秒超时，可随时点击取消。

展开 **查看过程**可核对读取、定位、试算、结果摘要和校验错误；这里不是模型内部推理记录。若助手循环查同一对象、定位错人或无法取得新资料，补充具体目标通常比重复发送原句更有效。

## 攻防对位分析：先核对事实，再看推演

### 不填 Key 也能做什么

进入 **AI分析战局**，从同一本战术本选择一攻一守。免登录演示提供预设攻防样例。此时已可查看图面简报和实际检索的教练资料；这些来自本地计算与资料检索，**不是模型生成的分析报告**。

图面简报描述站位、路线、区域等可见对象。例如图上画了阻挡线，不代表已证明真实保护人数；路线与区域相交，也不等于球员会在同一时间到达。

### 生成模型分析

1. 选择进攻、防守战术；需要时镜像防守以对齐图面，或选择某名球员的观察视角。分析中的镜像不修改原战术。
2. 设置覆盖假设：**未知、Cover 3 spot、Cover 3 Match、Cover 2 变体未确认、Cover 2 Read、man**。只看见安全卫站位时保留未知；宽泛的 Cover 2 不等于 Cover 2 Read。
3. 补充档数、距离、场地区域、已确认的保护或匹配规则及具体问题。真实美式橄榄球和 Madden 图示可分别选择分析情境；Madden 图不证明游戏机制。
4. 查看检索资料的适用条件、例外、观察对象和原始出处。必要时导入自己的资料，或用关键词缩小资料检索范围。
5. 填写模型设置，点击分析。需要停止时使用取消。
6. 按「如果……」阅读情景，核对观察对象、可能变化、可考虑动作和缺失信息。点击图面证据高亮对象，点击知识证据查看来源详情。

例如可提问：「第三档还差 6 码，已确认是 Cover 3 spot。从 Y 的视角看 Mesh，应该观察谁？请区分图上可见事实与球队规则未确认的部分。」如果并未确认覆盖，就把「已确认」改成未知，保留这一限制。

变更战术、覆盖、比赛情境或知识资料会使旧报告标为过期，相关在途请求会取消；旧报告与其原图快照保留，可回看，但不能当作新对局结论。更换模型连接不改变战术事实，新请求失败或取消也不会清空已有有效报告。

### 继续追问与采用建议

报告下方可针对当前情景继续追问，沿用该对局、版本和上次有效回答。输入改变使报告过期时，需先重新分析；追问失败会保留问题。不同战术本的分析会话相互隔离。

需要改图时选择将建议带到编辑器：系统打开对应进攻战术，把建议放入助手输入区，**不会直接修改战术**。核对后发送、查看预览，再接受整组或选定修改组。只读成员可讨论报告，不能发起写入提案。

### 云端和免登录演示的差别

| 项目 | 云端分析 | 免登录分析演示 |
|---|---|---|
| 数据来源 | 当前有读取权限的战术本 | 当前浏览器演示数据和预设样例 |
| 模型流程 | 读取图面、规则与授权资料的只读工具循环 | 本地检索后进行一次模型请求 |
| 服务商与 API 格式 | 与战术板助手共用上方五类服务商和三种格式 | 相同；浏览器直连受网络与 CORS 条件影响 |
| 资料与引用 | 只接收本次授权片段，校验引用 ID | 共用几何与引用 ID 校验，保留有限分析状态 |

取消 6／10 配额针对的是**战术板助手**。独立云端对位分析仍有单次运行预算（最多四次模型请求）及整次 90 秒超时；云端 AI 请求还可能触发短时频率保护。服务商本身也可能返回额度或速率错误。这些情况与旧的「本次助手查询上限」不同。

## 导入自己的知识资料

资料入口位于 **AI分析战局**的知识资料区。当前知识包服务于对位分析，不会自动变成战术板助手的长期记忆，也不会让原图自动可编辑。

| 文件 | 当前处理方式 |
|---|---|
| Markdown / TXT | 按标题与段落整理成文字卡片，长段落分片；不会自动认证覆盖类型与战术规则 |
| JSON | 导入符合项目格式的知识包，可保留来源、条件、例外、页码、区域与明确图文关联 |
| 含可选择文字的 PDF | 先用[本地预处理工具](ai-analysis/pdf-ingestion.md)生成 JSON，再导入 |
| 扫描 PDF、照片、纯战术图 | 需要另行 OCR 或人工补充说明；当前应用没有自动图像战术理解 |

普通文字资料可以这样整理后保存为 `.md`：

```markdown
# Cover 3 spot：球队已确认的规则

适用条件：这里写明已确认的覆盖和进攻概念。

观察对象：写明该位置实际应观察的球员或区域。

例外：写明哪些调整下不应沿用这条说明。
```

导入前应校对位置标签、否定词、阅读顺序和数字。需要机器可筛选的覆盖、条件和图文关系时，使用经过核对的结构化 JSON，格式见[知识库架构](ai-analysis/knowledge-architecture.md)。

当前单个导入文件最多 **1,000,000 字节、400 张卡片**；每次检索最多使用 **6 条／24,000 UTF-8 字节**的片段，不把整本资料库发送给模型。重复导入会合并去重；资料可移除，也可导出 JSON 备份。

知识保存在**当前设备、当前浏览器、当前战术本**，不随云端战术本同步。换设备或给队友使用时，需要导出后在对应设备导入。浏览器存储不可用时会报告错误，不应视作已保存成功。

页码和图片区域用于追溯来源。**同页不等于图文对应**；只有明确关联的图文才能作为关联资料展示。PDF 生成的 PNG 供人工核对，不会随 JSON 导入或自动发送给模型。当前尚未接入自动 OCR、图片视觉理解、向量检索、重排或共享云端知识库。

## 如何理解引用与分析边界

- 图面证据说明对象真实存在；知识证据让用户找到来源。引用 ID 有效，并不证明来源可靠或模型结论正确。
- 13 条内置双语原则有适用条件与例外，不构成完整球队安装手册；跑球、Four Verticals 等专用语料仍不完整。无相关命中时会保留有限分析。
- 静态站位不证明防守责任、保护分配、同时到达或真实阅读顺序。未知内容需要球队规则或教练补充。
- 分析不提供比赛胜率、EPA、码数预测或必然成功结论。可编辑路线也是示意几何，演练时序需要教练核对。
- 自动测试中的脚本化模型用于验证工具、预览和宿主流程，不代表所有真实模型都能正确理解每条自然语言指令。

## 数据会发送到哪里

| 入口 | 请求可能包含的内容 |
|---|---|
| 战术板助手 | 当前图面与笔记、球员姓名或号码，以及按工具读取的战术列表、名单、阵型和人员组概览；这些用于定位与编辑 |
| 独立攻防分析 | 所选攻防图面的战术对象、覆盖假设、比赛情境及本次检索片段；追问还携带上次有效报告、情景和问题。默认不发送完整名单、球员姓名、图片像素和教练笔记 |
| 主动勾选分析中的教练笔记 | 云端每套最多前 3,000 字，免登录演示每套最多前 2,000 字 |

密钥只保存在当前页面内存中。免登录版由浏览器请求服务商，云端版由服务器调用服务商；云端调用期间服务器会收到模型配置和密钥。不要在自然语言指令或资料正文中粘贴密钥。

## 常见问题

| 情况 | 处理方法 |
|---|---|
| 助手仍说不能新增 4–3 防守 | 核实运行的是已部署的新版本，并选择可编辑战术；已有防守时明确说「重置」，无需去 Madden 找防守条目 |
| 找不到某球员或选错同名位置 | 补充攻防侧、左右侧、姓名或号码；先核对预览中的实际标记 |
| 图面只有来源图片，不能改球员 | 原图没有可编辑坐标；选择已重建的可编辑条目，或使用现有原图转换流程；打开流程不代表已识别所有图片 |
| 应用时提示战术已改变 | 当前对象或相关人员、阵型已更新；重新生成并核对预览，避免覆盖后来修改 |
| 收起后想继续修改 | 重新打开助手，查看待确认提案并继续追问；只有显式放弃才取消草稿 |
| 分组选择提示依赖前序修改 | 保留创建目标或设置前提的修改组，再更新预览；不要跳过校验直接应用 |
| 分析报告标为旧版本 | 可回看报告原图；对当前输入重新分析后再追问或转入编辑 |
| 没有知识命中 | 核对概念词、覆盖假设与资料关键词；导入相关资料。无命中不应编造来源 |
| 导入后队友看不到资料 | 资料当前按本机战术本隔离；导出知识包，交由队友在自己的设备导入 |
| API 格式不兼容，或 HTTP 400／404 | 核对模型是否支持所选格式、地址前缀和最终端点；自定义网关不会被自动补 `/v1`，也不要把 Messages 当作 Claude Code 登录 |
| 网络或 CORS 错误 | 浏览器直连需服务商允许跨域；云端自定义主机需管理员允许。检查网络，不要仅凭界面可选就认定服务可达 |
| HTTP 401／403 | 核对所选服务商、模型权限和对应 Key；云端自定义主机还需检查允许列表 |
| 超时或 HTTP 429 | 检查服务商额度、速率和云端短时频率保护；稍后重试。它们区别于旧的助手总查询配额 |
| 模型拒绝、回复截断或结果格式无效 | 不把空白或不完整回复当作已执行。检查模型的工具与输出能力，必要时换兼容模型或减少单次请求的复杂度 |
| 手机或 iPad 不能开启数字模式 | 这些设备使用传统模式；仍可编辑和演练 |
| 已显示「准备好」但没导入或打印 | 点击 **继续**后完成真实文件选择、导入确认或打印操作 |

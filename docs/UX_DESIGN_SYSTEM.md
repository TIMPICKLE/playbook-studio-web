# Playbook Studio 交互与设计规范

本规范适用于战术编辑、战局分析、悬浮助手、战术库、球员与 DEPTH CHART，以及账号与工作区操作。战术图是主要工作对象；工具、属性和 AI 任务围绕图面提供支持。传统和数字模式共享操作语义，球场材质不决定功能反馈是否可见。

## 1. 布局与信息层级

| 层级 | 内容 | 规则 |
| --- | --- | --- |
| 全局 | 模块导航、当前工作区、权限和保存状态 | 当前位置有文字与选中标记；保存状态在紧凑布局下也可见 |
| 工作对象 | 战术名称、每方人数、攻防、当前选择 | 用户始终知道修改哪张图；5 人腰旗与 11 人战术不混淆 |
| 主画布 | 球员、路线、区域、标注与 AI 预览 | 优先保留画布可用面积，浮层不可盖住完成、取消和撤销入口 |
| 任务区 | 属性、AI 对话与提案 | 桌面共用一个右侧区域；触屏使用可收起面板，避免连续叠加多个抽屉 |
| 操作反馈 | 进行中、保存失败、可撤销结果 | 持续状态就地显示；Toast 只补充短时结果，不承担唯一的数据状态说明 |

桌面保留战术列表、主画布和一个任务区；窄屏/触屏用战术抽屉、画布和属性入口。手机不能仅缩小桌面：使用至少 44 CSS px 的操作控件、底部面板和不依赖悬停的说明。触控命中区域按屏幕坐标验证，不能用 SVG 世界坐标中的半径代替触控尺寸。

## 2. Design Tokens

`web/theme.css` 是语义 token 的唯一来源。其他样式通过变量消费，不再定义另一套全局 palette。迁移中保留旧名称作为映射，避免改动战术数据或第三方组件。

| 类别 | Token | 用途 |
| --- | --- | --- |
| 基底 | `--ui-bg`, `--ui-surface`, `--ui-surface-raised`, `--ui-surface-hover` | 石墨背景、操作区、浮层、悬停 |
| 文字 | `--ui-text`, `--ui-text-muted`, `--ui-text-subtle` | 正文、辅助信息、低频元数据；关键说明不使用过淡颜色 |
| 边界 | `--ui-border`, `--ui-border-strong` | 分组、输入边框与当前对象边界 |
| 强调 | `--ui-accent`, `--ui-on-accent` | 银色主要操作与深色文字，避免所有按钮同时争夺注意 |
| 焦点 | `--ui-focus`, `--ui-focus-ring` | 键盘焦点；不以细微背景变化代替清晰轮廓 |
| 状态 | `--ui-success`, `--ui-warning`, `--ui-danger`, `--ui-info` | 同时使用图标、文字和状态色；颜色不是唯一线索 |
| 提案 | `--ui-preview`, `--ui-preview-soft` | 尚未应用的 AI 提案，不与已应用/已保存状态混用 |
| 间距 | `--space-1` 至 `--space-8` | 4、8、12、16、20、24、32、40px |
| 字体 | `--font-ui`, `--font-display`, `--t-xs` 至 `--t-hero` | 系统字体负责操作与长文；紧凑展示字体只用于短标题/数字 |
| 形状 | `--r-inset`, `--r-control`, `--r-island`, `--r-pill` | 6、8、14px 与标签圆角；不把所有信息装进大圆角卡片 |
| 动效 | `--motion-fast`, `--motion-normal`, `--motion-panel`, `--ease-out` | 120、180、220ms 与统一缓动 |
| 层级 | `--z-header`, `--z-drawer`, `--z-assistant`, `--z-modal`, `--z-toast` | 导航、抽屉、助手、确认弹窗与通知的明确次序 |

正文默认 14px，辅助正文不小于 12px；手机输入 16px，避免系统自动缩放。长文行高 1.6–1.8；表格、代码和数值保留清晰对齐。状态文案必须说明对象、动作与结果。

## 3. 通用组件契约

| 组件 | 默认行为 | 错误/恢复与键盘 |
| --- | --- | --- |
| Button | 一个流程只突出当前主要动作；次要动作有边界或文字；危险操作用图标与文字 | Disabled 可解释原因；执行中阻止重复提交并保留文字；Enter/Space 遵循原生行为 |
| Input | 永久标签，辅助说明独立于 placeholder，焦点清晰 | 就地具体错误，`aria-invalid` 和关联说明；保留输入；中文选字 Enter 不提交 |
| Dialog | 简短确认、命名与文件选择使用原生 dialog；初始焦点与返回焦点明确 | Esc 退出当前层；破坏性默认不聚焦确认；重试不丢用户输入 |
| Sheet / Panel | 连续工作使用任务区，避免反复弹窗；打开不自动改变战术 | 关闭返回触发点，背景隔离与焦点循环由共享面板管理；手机可收起 |
| Dropdown | 当前值可见，键盘可操作，点击外部/Esc关闭 | 无鼠标悬停依赖；选中状态有勾选或文本 |
| Tooltip | 只解释短标签和快捷键 | 关键操作说明不能仅存在 tooltip；触屏保留明确入口和可见标签 |
| Toast | 动作结果简短、可关闭，可撤销时提供按钮 | 错误不只短暂闪过；长期失败就地保留重试入口；不盖住球场完成/撤销操作 |
| Loading | 启动即显示任务和对象；长任务有阶段说明和取消 | 不编造百分比；保留已有内容；取消和失败不误称已应用 |
| Empty | 说明缺什么并提供一个明确下一步 | 清空筛选、创建、导入或选择对象，不展示无意义占位卡片 |
| Error | 说明失败步骤、是否保留数据和下一步 | 重试/修改配置/恢复草稿，禁止仅显示“出错了”或直接清空界面 |

所有交互遵循：触发 → 即时反馈 → 执行结果 → 异常提示 → 恢复。提交成功、已应用到战术、已保存到本机/云端是不同状态，不合并为一个“完成”。

## 4. 选择、路线与撤销

- 进攻/防守使用形状、位置标签与颜色共同区分；选中使用轮廓，不覆盖球员身份。
- 选中、拖动、路线草稿、AI 提案是不同状态；切换面板不丢弃草稿。必须先明确完成/取消，不能因布局变化静默提交。
- 球场与属性编辑、AI 修改共用命令事务；一次拖动、一次组合提案各占一个撤销步骤。
- 多选时清楚显示数量及可执行批量动作。密集球员通过候选消歧/选中后拖动定位，不能盲目扩大可见棋子。
- 路线完成、取消、撤回一点在触屏可见；键盘 Enter 完成、Esc 取消；未完成路线与已保存路线有形状/文字差别。
- 所有可聚焦对象应支持相同激活规则；文字标注不例外。非拖动替代路径可在属性区精确调整。

## 5. AI 状态和结果

对话的目标工作区、当前战术与焦点对象可见。原图、待应用提案、已应用修改分别标记。预览不等于写入；关闭面板不应让用户误以为提案已保存。

状态至少区分：待输入、理解请求、调用工具、需要澄清、提案待确认、正在应用、已应用、失败、已取消、目标已变化。展示阶段事实与简短操作摘要，不将模型隐藏思考当作产品必需内容。

连续对话可在同一草稿上累积；手动编辑、切换战术、撤销或远端变化后，旧提案必须重新校验。错误应保留有效历史及可重试输入。模型配置与编辑状态独立，API Key 不出现在记录或截图里。

## 6. 动效规范

| 类型 | 规则 |
| --- | --- |
| 直接操作 | 棋子/控制点跟手，不使用延迟或弹簧追逐；松手后只产生一次事务 |
| 按钮与焦点 | 120ms 内颜色/边框反馈；键盘 focus 不做晃动和缩放 |
| 面板与状态 | 180–220ms 淡入/小幅位移，不反复播放整页入场 |
| AI 路线形变 | 保留领域插值，表达同一对象变更；用户可中止/撤销，不等待动画才能操作 |
| 装饰 | 默认静止；数字演示材质可按设备能力开启。粒子、光效与功能动效独立 |
| 减少动态 | `prefers-reduced-motion` 关闭位移/缩放与连续装饰，直接呈现结果；保留状态文字与必要对比 |

传统模式关闭 WebGL/粒子与材质动画，仍可有短促的功能反馈。`motion.js` 只读取用户减少动态偏好，不因传统渲染自动把必要交互动画全部关闭。任何性能退化都不能通过更改领域坐标或忽略输入来掩盖。

## 7. 样式所有权与维护

- `theme.css`：tokens、共享控件和跨模块状态样式；同一规则就地修改，不在末尾追加第二套同名定义。
- `component-layout.css`：导航、状态、任务区与真实可用宽度的容器布局。
- `responsive.css`：紧凑模式、手机、触屏和安全区；不重定义全局 palette。
- `board-assistant.css`：助手本体与浮动/停靠模式，消费语义tokens。
- `visual-mode.css`：传统/数字球场行为；不全局关闭按钮和面板的功能反馈。
- 各领域 CSS：只负责本领域结构，不覆盖其他模块。迁移时删除被替代的旧规则，保留必要兼容映射。

## 8. 验收

每阶段保留同一数据与视口的前后截图。Node/Happy DOM 检查状态和焦点，真实浏览器检查布局/遮挡/输入/动画，真机 Safari 检查触摸与软件键盘；不得以模拟DOM通过代替真机声明。

必须覆盖：1440×900、1280×720；iPad 横/竖屏；iPhone 390×844 和 375×667；中英文、编辑/只读、本地/云端、传统/数字、reduced-motion。核心路径包括密集球员选择、路线草稿继续、跨模块返回、AI 连续提案/应用/撤销、Madden加载取消、保存失败恢复和中文输入。

# AI 分析实用性评估

日期：2026-11-15。对象：PR #42 的美式橄榄球对局分析、设备本地知识库与 PDF 预处理路径。本报告是独立测试团队的场景评估，不是开发者自评，也不是教练临场效果试验。

## 判断概览

本功能有实际用途的部分是：在同一处核对攻防图、查阅适用条件明确的教练原则、导入球队自己的安装笔记，以及让模型引用当前对局证据。最适合战术学习、安装复习和分析准备。

它目前不等于完整的自动教练：默认知识只有 13 张精选卡，重点覆盖部分传球阅读、覆盖区别与施压边界；跑球、Four Verticals、保护分配等没有完整专用语料。图面计数、来源可追溯与模型回答是否正确，是三种不同的质量维度。

本轮实测发现并推动修复一项 P1：泛化问题中的“阅读、责任、时序”等词，会把不相关的传球概念填入资料区。修复前，真实 Inside Zone 示例竟召回 Hank、Spacing、Four Strong 和 Mesh；Four Verticals 对 man 也被 Mesh / Four Strong 填充。资料本身有条件提示，不能据此称为模型已编造战术事实，但这种检索噪声会消耗上下文、分散教练注意，并增加模型套用错误概念的风险。修复后独立复测 6/6 通过，24 个真实示例/覆盖组合也已重新执行并核对。

## 场景执行记录

测试使用项目真实 `starterWorkspace()` 的 Mesh、Flood、Four Verticals、Inside Zone 和 Cover 3 防守，另行构造小型球队笔记与两页 PDF。所有结果均由真实函数执行得到；没有调用真实模型服务商。

| 场景 | 具体操作与检查 | 观察结果 |
| --- | --- | --- |
| Mesh 对 man 的教学准备 | 选择 Mesh 与已确认 man，查看资料的帮助者、交叉时序与 read key | `mesh.man`、`mesh.traffic` 可召回，均有适用条件、例外和观察对象；通过 |
| 覆盖未确认 | 保留 unknown，显式查询 Smash / Cover 2 Read | 可召回条件化反例，适用状态保持 conditional；没有把双高站位自动识别为 Cover 2；通过 |
| Cover 2 未确认变体 | 选择宽泛 Cover 2，查询 Smash / corner | 有 `cover2.variant` 提醒先区分 spot-drop 与 Read；通过 |
| Cover 3 Match | Four Verticals 保持不变，改选 Match | `cover3.match` 说明安装与交接规则未知；这类通用覆盖边界应保留；通过 |
| Inside Zone 跑球 | 使用真实 Inside Zone，提问“第三档 6 码，请说明关键阅读点和防守反制” | 修复前召回六张不相关传球概念卡；修复后不再填入传球概念，真实无命中并提示资料缺口；复测通过 |
| Four Verticals 对 man | 相同通用问题，检查是否诚实暴露知识缺口 | 修复前返回 Mesh / Four Strong；修复后真实无命中，图面事实仍可用；复测通过 |
| Flood 对 Cover 3 spot | 查看有条件的强侧拉伸例卡，排除 Mesh 填充 | 修复后保留 `fourstrong.flood` 条件例卡，不混入 Mesh；复测通过 |
| 自有球队安装笔记 | 导入 Markdown，含独有术语 `Falconcheck`、red-zone trips 和 apex / flat 阅读 | 独有术语可找回，来源为 team，内容保留用户原文；通过 |
| 图示阻挡与真实保护 | 检查 Inside Zone 五条阻挡线的事实字段 | 只报告 blockingLines，不产生 protectors，也不推断 RB 任务；通过 |
| PDF 入库 | 实际创建两页 PDF，第一页可选中文字及矢量矩形，第二页空白；运行 CLI 并将输出送入 JS 校验和检索 | 成功提取一张 page 1 卡；page 2 标记 needs_ocr；可按独有术语召回；通过 |
| 图文出处边界 | 检查上述 PDF 卡与清单 | 没把矢量矩形解释为战术图；卡片 figures 为空；modelSawImages 与 ocrPerformed 均为 false；通过 |
| 资料发送范围 | 检查检索与授权模块边界 | 最多 6 条 / 24,000 UTF-8 字节的召回结果，单次导入知识片段另限 32 KB；不会把整本本机库静默送入模型；通过代码与回归契约核对 |

独立可复现测试见 `tests/qa-analysis-practical.test.mjs`。初次运行 6 项中 3 项通过、3 项失败，三项失败均复现上面的概念检索噪声；这是修复依据，不应从报告中删除。

## 修复后的复测

已重新运行 `node --test tests/qa-analysis-practical.test.mjs`，6 项全部通过。另对四套真实进攻战术 × 六种覆盖选项，共 24 个组合执行 `buildMatchup()` 并检查召回列表。关键变化：

- Inside Zone / Four Verticals 对 Cover 3 spot 或 man 不再被不同概念填充；当前缺少专用资料时真实无命中。
- Mesh 对 man 仍有 `mesh.man` / `mesh.traffic`，Flood 对 spot 仍有 `fourstrong.flood`。
- Cover 3 Match 的规则边界、宽泛 Cover 2 的变体提醒与 Cover 2 Read 的条件反例均保留。
- 自有球队笔记仍可按独有术语找回；本轮没有对未知球队术语套用内置战术分类规则。

核心修复对内置概念卡引入明确的概念词/受控别名检索条件，避免仅因“阅读、时序、责任”等泛词命中。它改进相关性，没有把词法命中改称为战术适用性已确认，也没有自动声称当前图中一定存在该概念。

## 实际价值与使用门槛

### 已经能帮助用户的任务

- 在发出模型请求之前核对真实图面对象和覆盖假设，避免把前线站位、播放速度或阻挡线数量当成实际责任。
- 把“可以考虑这个阅读”展开为适用条件、例外、防守反制与训练检查点；点击来源后可以回到原始教练文章。
- 将小规模球队安装笔记留在当前设备、当前战术本中，按独有术语找回，并保留页码或区域出处。
- 在模型报告中定位具体球员、路线和知识依据；程序可以拒绝本次对局以外的引用 ID。

### 会影响教练使用的门槛

| 项目 | 当前情况 | 优先级与建议 |
| --- | --- | --- |
| 概念检索噪声 | 初次实测出现，现已修复，独立 6/6 及 24 组合复查通过 | P1 已解决；保留真实示例回归，新增知识卡时同步维护概念检索条件 |
| 默认知识广度 | 13 张卡不是完整教练知识库，尤其不能覆盖全部跑球和 Four Verticals 安装 | P2；README 清楚说明范围，优先按用户真实球队资料扩展，不临时捏造大量知识卡 |
| PDF 使用门槛 | 需先在本机运行 Python / PyMuPDF，再导入 JSON；扫描件和图片需要 OCR 或人工说明 | P2；工程用户可以操作，非技术教练仍需未来的导入向导与处理状态 |
| 未结构化资料 | Markdown/PDF 提取保留原文，但不会自动确认覆盖、适用条件、例外或图意 | P2；重要球队安装应在知识包中人工补充条件字段，后续解析辅助仍需复核 |
| 资料规模 | 单包 1 MB / 400 卡，长手册需要按章节拆分；默认超限会明确报错 | P2；当前适合小型安装库，不应宣传成大规模本地多模态 RAG |
| 情境输入 | 档数、距离、场区与保护规则目前是自由文本 | P2；已有上下文足以表达问题，后续可加结构化选项减少歧义，仍保留自由说明 |
| 费用判断 | 云端最多四次模型请求，当前只在执行详情记录调用量和可用 token 使用量；没有跨服务商价格估计 | P2；提示多次请求与上限比显示未经核实的费用数字更可靠 |
| 云端共享 | 本机知识暂不随球队战术本同步，也不自动跨设备共享 | P2；UI 和 README 必须保留设备/战术本范围说明及导出备份入口 |

## 尚未得到的证据

1. 没有真实 API 凭证与实际生成记录，因此不能判定任何服务商的战术回答质量、稳定性、响应时长或费用已经通过。
2. 没有实战追踪数据，不能得出成功率、EPA、预计推进码数或逐人防守责任的有效性结论。
3. 没有教练/球员试用样本，不能将这份独立工程场景评估当作用户满意度研究。
4. 浏览器视觉、键盘与触屏验证由主工作线执行并单独记录；本报告没有通过源码阅读冒称完成真实设备验收。

## 合并建议

P1 概念检索噪声已修复并通过独立复测；从本团队执行的实用性场景看，没有剩余合并阻断项，可将它作为**有来源的战术学习与本机知识工作台**合并。真实模型回答质量、扫描件解析和大规模知识库能力继续保留为明确边界，不以引用 ID 校验通过替代教练复核。

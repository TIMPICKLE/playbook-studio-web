## 建议收敛（P1）

1. 本轮优先交付完整的“选择对局 → 本地简报和资料 → 模型情景 → 点证据定位”的闭环。自动改路线、3D 训练、视频追踪与统计预测分别保留后续边界，避免为了覆盖竞品功能而破坏现有编辑器。
2. 需要实用的提问入口：用户可写“第三档六码，重点看左侧外接”，可选择整体或球员视角；不必为一期加入大量缺省不可信的比赛数据表单。
3. 基于数量只报告“图示 X 条阻挡线 / Y 条防守移动线”，不能把阻挡线数直接称为保护人数，也不能把向前路线数直接称为冲传人数。只有标注契约足够时才推导。
4. 视觉层保持银灰、石墨进攻、低饱和铜色防守；在资料区和球场之间建立层级。减少长解释的默认展开，提供清晰的来源详情。移动端允许按球场、输入、分析顺序阅读，不要求把桌面的三栏压缩到手机。
5. 进度只显示真实已发生阶段；模型推理阶段使用不定进度，避免用定时器假装“正在验证规则”或“完成 83%”。
6. 模型报告中保留当前输入版本/本次检索来源。导入包和来源链接可追溯是完成条件；上传文件名、图片路径或 PDF 缩略图本身不等于视觉理解。

## 必须纳入的对照案例

- 同一 Flood，分别选择 Cover 3 spot、Cover 3 match 和 unknown；资料适用条件及未知说明应发生实质变化。
- 同一 Smash，选择宽泛 Cover 2 与 Cover 2 Read；禁止背诵“角卫上抢，所以 corner 一定空”。
- 只提供两深安全卫站位但未确认 coverage；不能自动升级为 Cover 2。
- 图面没有区域，知识库却命中很多条；仍显示图面责任未知，不能因卡片数多而 `complete`。
- 用户资料含绝对化断言、与精选规则冲突；不得把它宣传为已审阅知识。
- 同页两张战术图；显式引用 A 图时不能回补 B 图。
- 无 Key、API 401、取消后旧请求返回；三者都不能显示虚假的模型成功。
- 删除资料、换战术本、换语言、镜像战术；内容、来源与方位保持一致。

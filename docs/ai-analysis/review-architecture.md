# Team B · 独立架构与可靠性审阅

日期：2026-11-15。审阅基线：`1ddb37a`。对象：Team A 的 `task-plan.md` 及当前分析实现。

结论：**修订后通过**。方向与现有代码吻合；将知识库限定为可解释的本地检索、复用现有 LangGraph，优于同时引入多个不完整的处理系统。以下 P0 契约应纳入实施和测试。

## 已核查的架构事实

- 云端请求当前最多 12,000 bytes；LangGraph 对局上下文另有 120,000 bytes 上限。只增加 HTTP 上限不能解决整个上下文预算。
- 现有工具先强制 `get_matchup_context`，后续按 4 次模型调用、2 个工具轮次、6 个工具调用执行，并允许有界修复。
- `runMatchupAgent` 当前使用 `knowledge.length` 判断完整性；补充通用规则后，必须增加独立的信息充分性判定。
- 静态演示是独立单次模型调用，没有云端工具循环；应共用知识契约和检索，保留其能力边界。
- 当前 `decodeWorkspace()` 丢弃未声明字段。按工作区保存本机知识包是本轮合理边界；不能把它描述为球队云端共享知识。

## P0：必须修订

| 问题 | 实施约束 | 验证 |
| --- | --- | --- |
| 来源或卡片 ID 碰撞可能替换精选规则 | 保留内置命名空间；同 ID 不同内容拒绝或显式版本化；来源身份基于内容/版本，不能仅用文件名；重复导入幂等 | 相同文件重复导入不重复；同名不同文件不覆盖；导入卡无法冒充内置来源 |
| 本地大知识包会挤爆模型上下文 | 分开设置导入文件、来源数、卡片数、字段长度、总存储、单次发送和最终模型上下文预算；在模型请求前失败并给出可操作提示 | 超大字段/大量来源/复杂图与知识同时出现均有界；不先产生付费模型请求再失败 |
| 检索工具的可见范围可能与 UI 不一致 | 前端明确本次发送的知识子集；服务端重新校验；工具只搜索本次授权、验证后的有限集合，不声称搜索整本未发送资料 | 未发送条目无法被工具读到；来源列表与模型接收 evidence 集合一致 |

## P1：需要随实现完成

1. 存储不可用、配额已满、损坏的旧 JSON 均显示真实状态；不得显示“已保存”后丢失。删除资料后检索立即排除对应卡。
2. 新来源链接只允许经过验证的 HTTPS；展示转义后的纯文本。`data:`、本机路径和 `javascript:` 不应成为可点击源链接。图片路径只是 provenance，不等于已经发送像素。
3. 检索排名只表示相关性，不能显示成功概率或校准置信度。没有命中时返回空集；不要固定补入热门概念并称为命中。
4. 中英文别名测试应涵盖 Cover 3/三区、man/盯人、Mesh/交叉等，同时避免 Cover 2 与 Cover 2 Read、spot 与 match 的规则串用。
5. 保留已有证据 ID、情景字段、模型协议、修复与取消语义。旧调用无知识参数时继续工作。新增静态演示证据允许兼容旧模型未返回引用的情况，但不能伪造引用。
6. UI 进度必须反映真实本地准备或远程请求状态；没有流式阶段消息时不能展示假装服务端正在运行的节点。

## 建议测试清单

- 知识校验：未知版本、重复 ID、未定义来源、畸形页码/区域、异常嵌套、过长内容、内置命名空间冲突。
- 检索：双语同义查询、显式 coverage 过滤、未知 coverage、无命中、同分稳定顺序、top-K 和字符预算、删除后不再召回。
- 来源：内容更新版本改变；同页多图的 explicit linkage；图像引用和图片已分析状态分离。
- 云端：请求 cap、上下文 cap、无知识旧请求、未召回引用拒绝、revision 变化、取消、Worker isolate 实际运行。
- 静态：共用检索与白名单；模型未返回引用不制造引用；模型伪造引用报错；不会声称存在云端 Agent 工具。
- UI：每工作区隔离、异步导入竞争、配额失败、来源删除、查询变化立即刷新检索、引用与画布高亮、英文无遗留 key。
- 集成：`npm run check`、`npm run typecheck`、`npm test`、`npm run build`；浏览器不可用时如实记录验证限制。

本审阅没有修改实现代码。

# PDF 资料接入：可复现的本地预处理

这个工具把 PDF 中**实际存在的可选中文本**整理为分析工作台支持的知识包，并保留原始文件、页码和文本区域。它在本机运行，不调用模型，也不访问网络。

扫描 PDF、照片和只有路线图的页面仍需要 OCR 或人工补充说明。生成 PNG 只用于核对出处，不代表模型理解了图片。无法形成有效归一化区域的文字块会被跳过，并在清单的 `skippedTextRegions` 中标明；不会输出工作台无法校验的零面积坐标。

## 使用

需要 Python 3.10+ 与 PyMuPDF。本项目的 JavaScript 运行时不依赖 Python；只有使用这条离线预处理路径才需要安装它。

```bash
python -m pip install PyMuPDF
python scripts/ingest-football-knowledge.py \
  --input ./playbooks/team-install.pdf \
  --output ./knowledge/team-install.json \
  --title "球队安装手册" \
  --render-pages
```

然后在 AI 分析工作台的知识资料区导入 `team-install.json`。浏览器知识库按当前战术本保存在本机，云端球队成员不会自动获得这份资料。

输出包含三部分：

| 输出 | 内容 | 用途 |
| --- | --- | --- |
| `team-install.json` | 有界文本卡与来源元数据 | 导入工作台，参与实际文本检索 |
| `team-install.manifest.json` | 每页提取状态、卡片 ID、图片区域和限制 | 检查哪些页需要 OCR，追溯页面与区域 |
| `pdf-<内容哈希>-assets/` | 原页预览及实际嵌入图片区域的 PNG | 人工离线核对；不会随 JSON 导入或自动发送模型 |

不需要图片预览时可以省略 `--render-pages`。仍会输出图片区域坐标，但不生成图片文件。

## 来源与图文关联

来源 ID 为 PDF 文件字节的 SHA-256 摘要派生值，`revision` 保存完整摘要。相同文件重复处理产生相同来源和卡片 ID；PDF 内容改变后产生新的来源身份。更改 `--title` 只改变展示标题，不改变文件身份。

卡片页码从 1 开始。`regionId` 表示真实提取的文本块；`bbox` 为 `[x0, y0, x1, y1]`，各值在 `[0,1]` 内，以**未旋转页面的左上角**为原点。清单保存 PDF 页面的尺寸和原始旋转角，预览使用同一未旋转坐标系。

每张卡只有实际抽取出的文本，不会自动补充战术标签、覆盖类型或战术结论。例如：

```json
{
  "id": "pdf-<hash>-p3-text-1-1",
  "sourceId": "team:pdf:<hash>",
  "title": "球队安装手册 · p.3 · 1.1",
  "content": "这里是 PDF 中实际存在的说明文字。",
  "tags": [],
  "coverages": [],
  "appliesWhen": [],
  "exceptions": [],
  "page": 3,
  "regionId": "text-1-1",
  "bbox": [0.08, 0.12, 0.88, 0.24],
  "figures": []
}
```

**同页不等于对应。** 一页可能有多张战术图，因此提取器不会把本页所有图片自动附加到所有文字卡。文本卡的 `figures` 默认保持空数组；图片清单的 `linkedCardIds` 也保持空数组。只有人工或后续可靠布局解析确认图文关系后，才应建立明确关联。

图片区域来自 PDF 实际嵌入图片的位置。它可能是战术图、扫描整页、照片或装饰图片；工具没有对它进行语义分类。矢量线条绘制的战术图可能不会成为单独的图片区域，但仍可在整页预览中查看。

## 需要 OCR 的页面

没有可选中文本的页在清单中标记为 `needs_ocr`，可能是扫描页、纯图页或空白页。该页不会生成虚构文字卡。

建议处理顺序：

1. 在清单检查 `needs_ocr` 页，并人工查看原页。
2. 对扫描文字执行本地 OCR，或由教练补充对应图的文字说明。
3. 校对位置标签、路线名称、阅读顺序、否定词和数字；这些 OCR 错误会直接改变战术含义。
4. 保留原 `sourceId`、页码与明确的图区域关系，另行整理为经过审核的知识卡。
5. 补充适用覆盖、条件与例外，再导入工作台。

若整份文件没有文字，工具仍输出清单和空卡片 JSON，便于诊断；空包不构成可用的知识库。不要将生成文件数当成识别成功。

含少量页脚文字的扫描页可能仍被标为 `text_extracted`，这只说明找到了文字，不保证正文完整。正式用于分析前应检查预览与提取内容。

## 大文档边界

默认上限为：输入 PDF 100 MiB、1,000 页、400 张卡、每卡 4,000 字符、知识包 JSON 1 MB（1,000,000 字节，与工作台导入上限一致）。每页最多记录 40 个嵌入图片位置，额外数量写入清单。预览最长边不超过 1,200 像素。

超过卡片数或知识包字节限制时，默认明确失败，避免用户误以为整本已入库。优先把手册按安装主题、覆盖体系或章节拆分后处理。

确实需要只取一个有界子集时，显式使用：

```bash
python scripts/ingest-football-knowledge.py \
  --input ./playbooks/team-install.pdf \
  --output ./knowledge/team-install-partial.json \
  --truncate
```

此时摘要和清单均显示 `truncated: true` 及 `excludedCards` / `excludedCardCount`；被排除的内容没有进入知识包。卡片上限不会改变每卡与整体字节上限。

文件哈希支持识别资料身份，不证明资料正确。PDF 的作者、球队规则版本和适用比赛人数仍需由资料负责人确认。

## 验证

执行离线行为测试：

```bash
python scripts/test-ingest-football-knowledge.py
```

测试程序在临时目录创建两页合成 PDF：第一页有两段文字和两张独立图片；第二页只有图片。它验证确定性来源与卡片 ID、1-based 页码、图片文件可用、同页图片没有被虚假绑定、扫描页没有伪造 OCR 文本、明确截断及空白页行为。

JavaScript 应用回归测试与 Python 预处理器分开执行，避免让正常浏览器/Worker 构建依赖 PDF 工具链。
